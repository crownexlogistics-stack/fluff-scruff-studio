## AI Receptionist Team Inbox

Build a mobile-first team inbox so all staff (not just directors) can claim and resolve cases generated by the AI receptionist — missed opportunities, voicemails, callback requests, and "running late" notifications — with in-app notifications and auto-population from the existing AI call pipeline.

---

### 1. Database (one migration)

**Table `ai_inbox_cases`**
Fields per spec: `id, case_type, status, caller_number, caller_name, dog_name, summary, full_transcript jsonb, call_duration_seconds, assigned_to (→ staff.id), assigned_at, resolved_at, resolution_note, booking_id (→ bookings.id), appointment_time, minutes_late, created_at, updated_at`.
Indexes on `(status, case_type, created_at desc)` and `(assigned_to, status)`.

**Table `ai_inbox_notifications`**
`id, staff_id (→ staff.id), case_id (→ ai_inbox_cases.id), message, is_read, created_at`.
Index on `(staff_id, is_read, created_at desc)`.

**RLS**

`ai_inbox_cases`:
- SELECT: any authenticated user can read `status='unassigned'`; staff can read rows where `assigned_to` matches their staff row (joined via `staff.auth_user_id = auth.uid()`); directors (`has_role(auth.uid(),'director')`) can read everything; resolved rows readable by all authenticated staff (so the "recently resolved" section works).
- INSERT: any authenticated user + service role.
- UPDATE: own assigned rows + directors.

`ai_inbox_notifications`:
- SELECT: only rows where `staff_id` belongs to current user.
- UPDATE (mark read): same.
- INSERT: service role only (edge functions / triggers).

**Trigger `auto_create_inbox_case_from_ai_call`**
On INSERT into `ai_call_logs`, if `outcome='transferred'` OR `summary ILIKE` any of `%unable%|%technical%|%difficulty%`, insert a `missed_opportunity` case (caller_number, summary, full_transcript, call_duration_seconds).

`updated_at` trigger using existing `update_updated_at_column()`.

**Realtime**: add both new tables to `supabase_realtime` publication.

### 2. Edge functions

**`elevenlabs-call-webhook`** — extend the existing post-processing block:
- If derived `outcome === 'voicemail'`: insert `case_type='message'` (caller_name + message extracted from last caller transcript line, full transcript stored).
- If `data?.analysis?.transfer_successful === false` AND a phone/name was captured: insert `case_type='callback_requested'`.
Existing behaviour (upsert `ai_call_logs`, missed-opportunity email) is untouched — the trigger creates the missed-opportunity case automatically.

**`phone-booking`** — add `action: "log_running_late"`:
1. Resolve customer phone candidates (existing helper).
2. `bookings` lookup for `booking_date = today` (London) for that phone, status in Pending/Confirmed; pick the row matching `appointment_time` if provided, otherwise the next upcoming.
3. Read `staff_id` from booking; insert `ai_inbox_cases` row with `case_type='running_late', status='assigned', assigned_to=staff_id, assigned_at=now(), appointment_time, minutes_late, caller_name, dog_name, caller_number, booking_id`.
4. Insert `ai_inbox_notifications` row for that groomer with the spec message.
5. Return `{ success, case_id, groomer_name }` with descriptive errors on every failure path. No other actions touched.

### 3. Frontend

**Routing** — `/ai-inbox` in `src/App.tsx`, allowed roles `groomer, manager, director` (volunteer/work_placement excluded).

**Sidebar** — add entry in `AppSidebar` with `Inbox` (lucide) icon and a red badge driven by a new `useUnassignedInboxCount` hook (counts all `status='unassigned'` rows; live via realtime channel).

**Page `src/pages/AIInboxPage.tsx`** with five tabs in a horizontally scrollable strip (no wrap on mobile):
1. Missed Opportunities
2. Messages
3. Callbacks
4. Running Late
5. My Cases (default tab on mobile for groomers)

Each non-MyCases tab renders two sections via a shared `<CaseList>` component:
- **Unassigned Pool** — claim button (full-width on mobile, ≥44px), tappable `tel:` link on the phone, swipe-right to claim / swipe-left to dismiss (uses `framer-motion` drag with thresholds).
- **Recently Resolved** — last 10 resolved of that type with resolver name + note.

`My Cases` tab lists assigned cases with a "Mark as resolved" dialog containing a per-tab preset list of resolution options + free-text. Director sees everyone's assigned cases here.

**Running Late banner** — a sticky full-width red pulsing alert at the top of the page when the current user has any `running_late` case `status='assigned'`. Tapping scrolls to / opens the case.

**Notification bell** — `<InboxBellButton>` placed in `AppLayout` and `GroomerLayout` headers. Dropdown lists recent notifications, "mark all read" button, click navigates to `/ai-inbox` with the case opened.

**Auto-refresh & freshness**
- React Query with `refetchInterval: 60_000` and `refetchOnWindowFocus: true`.
- `visibilitychange` listener triggers refetch when tab becomes visible.
- "Last updated HH:MM" line at top.
- Realtime subscriptions on both tables for instant updates.

**Visual tokens** (using existing semantic colors in `index.css`):
- Unassigned: `border-l-4 border-amber-500`
- Assigned: `border-l-4 border-blue-500`
- Resolved: `border-l-4 border-emerald-500`
- Urgent (running late): `border-l-4 border-destructive animate-pulse`
- Cards: `p-4 sm:p-5`, body text `text-base`, names/times `text-lg`.

### Technical notes
- Staff row resolution everywhere uses `staff.auth_user_id = auth.uid()` — no role escalation, no client-side trust.
- All RLS predicates use `has_role()` (security definer) to avoid recursion.
- Swipe gestures use `framer-motion` (already in repo) — desktop uses buttons only.
- Offline read works because React Query keeps last successful data in cache; no service worker added.
